API Gateway & BFF Microservice
A centralized microservice acting as both an API Gateway and a Backend-for-Frontend (BFF). Built with Python and FastAPI, this service proxies standard client requests and aggregates data from multiple external APIs into a single response.

Created using a tutorial made by Gemini AI.

Features
Backend-for-Frontend (BFF) Aggregation: Fetches data from multiple external APIs concurrently and merges the results into a single JSON payload.

API Gateway Proxy: A catch-all route that dynamically forwards requests to target destinations based on a centralized configuration.

Centralized Route Management: API routes and authentication requirements are managed via a single ROUTE_CONFIG dictionary, preventing code duplication.

Fault Isolation: Specific httpx.RequestError exception handling ensures that a timeout or failure from one external API does not crash the entire aggregation loop.

Cloud-Ready: Includes a root health check endpoint for liveness probes and dynamic port binding for platforms like Railway, Heroku, or Google Cloud Run.

Tech Stack
Framework: FastAPI

HTTP Client: httpx (Asynchronous)

Server: Uvicorn

Testing: Pytest, unittest.mock

Installation
Clone the repository:
git clone <your-repo-url>
cd API-Gateway-Microservice

Install the required dependencies:
pip install fastapi uvicorn httpx pytest
Start the local server:
python main.py

The server runs on [http://0.0.0.0:8000](http://0.0.0.0:8000) locally, or automatically binds to the PORT environment variable in production.

Configuration
External APIs are managed in the ROUTE_CONFIG dictionary inside main.py. To add a new routing target, provide its base URL and a boolean flag indicating if it requires authentication.

ROUTE_CONFIG = {
    "catfacts": {
        "base_url": "https://catfact.ninja/fact",
        "needs_key": False
    },
    "usda": {
        "base_url": "https://api.sc.egov.usda.gov/plants",
        "needs_key": True
    }
}
API keys are managed securely in the API_SECRET_KEYS dictionary. If needs_key is true, the gateway automatically injects the corresponding key into the HTTP Authorization header as a Bearer token.

API Reference
Interactive API documentation is automatically generated by FastAPI and available at /docs when the server is running.

1. Health Check
Endpoint: GET /

Description: Liveness probe utilized by cloud platforms to verify service health.

Response:
{
    "Message": "API Service is Running..."
}
2. Aggregator (BFF)
Endpoint: POST /aggregate

Description: Accepts a JSON dictionary of API names and their respective query parameters. It queries all requested APIs and returns a merged dictionary of the results.

Payload Example:
{
    "catfacts": {"limit": 1},
    "usda": {"zone": 4}
}
3. API Proxy (Gateway)
Endpoint: ANY /{path}

Description: Routes standard HTTP traffic (GET, POST, PUT, DELETE) directly to the configured external endpoint and returns the raw JSON response.

Example: GET /catfacts automatically proxies to [https://catfact.ninja/fact](https://catfact.ninja/fact).

Testing
This microservice uses Pytest for unit testing, employing unittest.mock.patch to intercept asynchronous httpx network calls and simulate API responses without requiring an active internet connection.

Run the test suite:
pytest test_suite.py
